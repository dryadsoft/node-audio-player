# iPad 수업노트 복구

## 변경

- 수업노트 필기 JSON은 4MiB까지, 해당 API의 HTTP JSON 본문은 NestJS·Nginx 모두 8MiB까지 받습니다. 일반 API의 NestJS JSON 2MiB, 출석부 사진 경로 10MiB는 유지합니다.
- 공용 필기 패키지 v0.2.1은 새 좌표를 소수점 5자리, 압력을 3자리로 저장합니다. 기존 필기·획 ID·점은 변환하거나 삭제하지 않습니다.
- Pencil 접촉 중 지우개를 포함한 손바닥 이동을 막습니다. 남아 있는 손바닥 터치는 이동을 시작하지 않으며 Pencil을 뗀 뒤 새 손가락 제스처로 이동합니다.
- 저장 오류·충돌 상세와 오프라인 상태는 사용자가 여는 패널에 표시합니다. 저장 상태 변화가 필기장 위에 새 행을 삽입하지 않습니다.
- 음악·강의계획서 등 JSON 요청은 캐시를 우회하고 10초 제한과 로그인 응답 검증을 적용합니다. 실패를 빈 목록과 구분하고 다시 시도·다시 로그인을 제공합니다. 재로그인 후 경로·필터를 유지합니다.

## 기존 기록 복구 순서

1. 홈 화면 앱(PWA)과 Safari에서 각각 수업노트의 오프라인 상태 버튼을 열어 **기기 기록 내보내기**로 백업합니다. 두 파일을 구분해 보관합니다. 앱 삭제나 사이트 데이터 초기화는 하지 않습니다.
2. 서버 수정 배포 후 기존 PWA를 열어 둔 상태에서 **동기화 재시도**를 누릅니다. 크기 제한으로 거절됐던 기록은 기존 앱에서도 다시 전송할 수 있습니다.
3. PWA·Safari 각각 온라인 상태에서 재시도합니다. 서로 추가한 획은 기준본과 서버 최신본을 비교해 병합됩니다. 같은 획 수정·삭제 충돌은 저장 상태 상세에서 선택합니다.
4. 양쪽의 미전송 건수가 0이고 실제 필기가 일치하는지 확인합니다. 확인 전에는 어느 쪽 기록도 지우거나 다른 쪽으로 덮어쓰지 않습니다.
5. 기록이 보존된 뒤 앱과 같은 사이트의 탭을 모두 닫고 다시 열면 대기 중인 새 PWA 버전이 적용됩니다. 앱이 자동으로 강제 갱신하지 않습니다.

PWA·Safari의 저장소와 로그인 상태는 각각 확인해야 합니다. Wi-Fi에서만 목록을 읽지 못하면 오류 표시와 재로그인을 확인하고 가능한 경우 휴대폰 핫스팟과 비교합니다. 이 변경은 실제 iPad 네트워크 경로가 정상임을 증명하지 않습니다.

## 검증

- 독립된 두 IndexedDB 저장소에서 PWA의 HTTP 400 실패 기록과 Safari의 추가 필기를 재시도·병합·재실행해 보존합니다.
- 2MiB 초과 기존 정밀도 필기의 HTTP 저장과 409 충돌, 필기 4MiB 및 본문 8MiB 초과 거절을 검증합니다.
- 필기 중 저장 오류가 발생해도 편집기 DOM과 앞 요소가 유지되고, 사용자가 열기 전 상세 패널이 나타나지 않는지 검증합니다.
- 실제 iPad의 Pencil·손바닥·스크롤 안정성과 두 실행 환경의 필기 일치는 별도 기기 수용 검증입니다.

로컬 Chromium의 820×1180 iframe에서 Pencil 접촉 중 저장 오류 발생과 후속 저장 완료를 모의 검증했습니다. 캔버스 위치·크기와 스크롤이 동일했고 DOM도 유지됐습니다. 이는 실제 iPad 입력 검증을 대신하지 않습니다.
